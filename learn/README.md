# Learn contract-driven BDD by building it yourself

This folder teaches the workflow in `../sample` by having you **rebuild it from an empty directory**, one small verified step at a time, and then extend it on your own.

```
learn/
├── README.md               ← you are here
├── tutorial/               ← the step-by-step guide (read in order)
│   ├── 00-big-picture.md
│   ├── 01-web-skeleton.md
│   ├── 02-web-app.md
│   ├── 03-vitest-browser-mode.md
│   ├── 04-contract-recorder.md
│   ├── 05-flow-tests.md
│   ├── 06-test-project.md
│   ├── 07-generator.md
│   ├── 08-selenium-support.md
│   ├── 09-page-objects-and-steps.md
│   ├── 10-run-everything.md
│   ├── 11-break-it-on-purpose.md
│   └── 12-practice.md
└── workspace/              ← you build here: workspace/web and workspace/tests
```

## How to use it

1. Start with [tutorial/00-big-picture.md](tutorial/00-big-picture.md). It explains the idea, the vocabulary and the tools, and checks your machine.
2. Go to `learn/workspace` once (chapter 01 shows how) and **run every command from there**. Commands that need `web/` or `tests/` are written as `(cd web && …)` / `(cd tests && …)`, so you never lose your place.
3. Work through the chapters in order. Each one ends with a **✅ Checkpoint**: a command and the output you should see. Don't move on until it matches.
4. Type the code rather than copy it where you can. Every file is printed in full, followed by an explanation of the parts that matter.
5. When you're stuck, compare with `../sample`. Your finished `workspace/` should match `sample/` file for file, so the sample is your answer key. (The only difference is that your `web/package.json` pins exact versions.)
6. Finish with the practice chapter ([12-practice.md](tutorial/12-practice.md)). You'll add a new acceptance criterion end to end with no code to copy.

## Time

About 3–4 hours for chapters 00–10 if you type everything. Chapters 11–12 take another 1–2 hours.

## What you'll be able to explain at the end

- Why a **flow** (state → action → wait → state → outcome) is recorded, and not just an HTML snapshot.
- What a **UI contract** file contains and who owns it.
- Why **locators are generated by a program** (`web/tools/generate-locators`, TypeScript) and never by hand or by AI.
- What the **AI agent** is allowed to write (page objects, step definitions) and what it may never touch.
- How the `@AC-nnn` tag links a Gherkin scenario, a flow test, a contract and a CI coverage check.
- Which safety nets catch UI drift, broken persistence and missing test IDs, and where each one fires.
